# ATELI - The Devin Killer (a.k.a. "데빈 학살자")

> "모델은 안 만든다. 대신 모든 다른 걸로 박살낸다."
> — ateli 1차 선언문, 2026

---

## 0. 한 줄 요약

**ateli = Claude Opus 베이스 + 미친 툴체인 + 변태같이 정밀한 RAG + 고객 전용 클라우드 + 모든 서피스에서 접근**

이거 한 줄로 Devin/Imbue/Cognition 다 발라버리는 게 목표다.

---

## 1. 왜 이게 되는가 (포지셔닝)

### Devin의 한계
- 자체 모델 안 쓰고 Claude/GPT 라우팅하는데 그걸 숨기려 함
- 컴퓨터 사용(VM 띄워서 클릭/타이핑)이 자랑인데 그게 사실 제일 느리고 비쌈
- 가격은 비싼데 결과물은 가끔 환각
- "혼자 며칠 일함" 마케팅인데 실제론 사람이 계속 봐줘야 함

### Imbue의 한계
- 자체 70B 모델 만든다고 했는데 Opus/Sonnet보다 똑똑할 리가 없음
- "추론 특화"라는데 그거 이미 thinking mode로 다 됨
- B2B 셀프호스팅 노리는 듯한데 그건 차별점이 아니라 필수임

### ateli의 베팅
1. **모델은 절대 안 만든다.** Anthropic이 알아서 더 똑똑하게 만들어줄 거다. 우리는 그 위에서 논다.
2. **툴이 모델보다 더 중요한 시대다.** 인간도 똑똑해서 일 잘하는 게 아니라 도구 잘 써서 잘함.
3. **RAG와 컨텍스트 큐레이션이 진짜 모트(moat)다.** 모델 가중치는 못 가져가도 회사별 지식 그래프는 락인됨.
4. **클라우드는 고객 VPC에 들어간다.** 데이터 주권 = 엔터프라이즈 락인.
5. **모든 서피스가 동일한 에이전트로 연결된다.** Slack에서 시작한 작업이 IDE에서 이어지고 모바일에서 검토됨.

## 2. 미친 툴 아이디어 (이게 핵심)

Devin이 "컴퓨터 띄우고 클릭함"이면, ateli는 그 위로 다음 단계를 간다.

### 2.1. ⏰ Time-Travel Debugger (시간여행 디버거)
- 모든 코드 실행을 rr/Pernosco 스타일로 결정론적 녹화
- 에이전트가 버그 만나면 "10초 전으로 돌아가서 변수 X가 언제 NaN 됐는지" 역방향 추적
- 사람 개발자도 못 하는 짓을 에이전트가 함
- **비용**: 비싸다. 근데 쓸 만한 가치 있음. 결정론적 리플레이는 디버깅의 성배.

### 2.2. 🌌 Parallel Reality Testing (평행우주 테스트)
- 코드 변경 하나에 대해 동시에 50개 fork 돌려서 "어느 가설이 맞는지" 확인
- "if문 빼면 어떻게 되지?" → 5초 안에 50개 시나리오 결과 비교
- Git worktree 50개 + 컨테이너 50개 = 클라우드 청구서 폭발 = 우리는 좋음 ㅋㅋ

### 2.3. 👻 Production Shadow Mode (프로덕션 그림자 모드)
- 고객이 허락한 범위 내에서 ateli가 프로덕션 트래픽의 복사본을 받음
- 새 코드를 그림자 환경에 배포 → 실제 트래픽으로 자동 회귀 테스트
- 사람 QA 필요 없음. "1% 트래픽이 새 코드에서 다른 응답 보임" 자동 감지
- **이게 진짜 Devin이 못 따라오는 거**

### 2.4. 🖼️ Visual Regression Agent (시각 회귀 에이전트)
- 모든 UI 변경 시 픽셀 단위 + 시맨틱 단위 비교
- "버튼 1px 옮겨졌는데 의도된 거임?" 자동 질문
- Multi-modal Claude가 스크린샷 보고 "이거 디자인 시스템 위반인데?" 라고 알려줌
- Figma 연동: Figma 디자인 vs 구현 픽셀 자동 diff

### 2.5. 🎙️ Voice + Screen Capture 입력
- 개발자가 화면 녹화하면서 "여기 이거 클릭하면 이런 게 떠야 하는데 안 뜸" 말함
- ateli가 영상 + 음성 보고 바로 재현 → 디버깅 → 수정 → PR
- 티켓 작성 단계 자체가 없어짐

### 2.6. 🤖 Synthetic User Swarm (가짜 유저 떼)
- LLM으로 페르소나 100개 생성 ("성격 급한 50대 남자", "꼼꼼한 20대 디자이너" 등)
- 신기능 배포 전 가짜 유저 100명이 동시에 써봄
- 행동 로그 + 불만 코멘트 자동 수집
- "야 이 페르소나 47번이 자꾸 여기서 막힘. 봐봐"

### 2.7. 🧬 Code Archaeology Agent (코드 고고학자)
- "이 코드 왜 이렇게 짜져 있냐?" 질문 시
- git blame → PR description → Slack 검색 → 회의록 → 디자인 문서 까지 추적
- "2년 전에 김XX가 이런 이유로 짰고, 그때 토론은 이 슬랙 스레드에 있고, 결정 근거는 이 문서임" 한 번에 답변
- **이거 사람도 못 함. 에이전트만 가능.**

### 2.8. 💰 Cost-Aware Execution Planner
- 모든 작업 시작 전에 "Opus로 할까 Sonnet으로 할까 Haiku로 할까" 비용/품질 트레이드오프 계산
- "이 작업 Opus로 하면 $4, Sonnet으로 하면 $0.3인데 품질 차이는 5% 예상" 보고
- 고객이 예산 정해두면 자동으로 최적 라우팅
- 단순 리팩토링은 Haiku, 아키텍처 결정은 Opus, 코드 리뷰는 Sonnet

### 2.9. 🪞 Self-Critique Loop (자기 비판 루프)
- 코드 짜고 끝이 아니라, 다른 페르소나의 ateli가 검토함
- 페르소나: "Linus Torvalds급 까칠한 리뷰어", "보안 편집증 환자", "성능 광인", "신입 개발자(가독성 체크)"
- 4명 다 통과해야 PR 올림

### 2.10. 🔬 Hardware-in-the-Loop (실기기 테스트)
- 임베디드/IoT/모바일 개발자 위해 실제 디바이스 팜 연동
- AWS Device Farm, BrowserStack, 자체 호스팅 라즈베리파이 클러스터까지
- "iPhone 13에서만 크래시 남" → ateli가 직접 실기기에서 재현

### 2.11. 🧠 Long-Horizon Planning with Replay
- 1주일짜리 작업을 계획 → 매 시간마다 진행 상황 자체 평가 → 막히면 사람한테 ping
- 중요: "막혔는데 막힌 줄 모르고 계속 도는" Devin 망 패턴 방지
- 시간/비용 예산 자동 트래킹, 초과 시 자동 일시정지

### 2.12. 🕸️ Knowledge Graph Builder
- 회사 모든 코드/문서/슬랙/지라/노션을 통합한 살아있는 지식 그래프
- "결제 시스템" 노드 클릭 → 관련 코드 + 담당자 + 최근 이슈 + SLA + 의존성 다 보임
- ateli가 작업 시작할 때 이 그래프 먼저 참조 → 컨텍스트 미스 0

### 2.13. 🎬 Dry-Run Theater (드라이런 극장)
- 위험한 작업 (DB 마이그레이션, 인프라 변경) 전에 시뮬레이션 환경에서 먼저 실행
- 결과를 영상처럼 보여줌: "이 마이그레이션 실행하면 이 30개 쿼리 락걸림, 평균 12초 다운타임 예상"
- 고객 OK 누르면 실제 실행

### 2.14. 🛡️ Self-Healing Infrastructure Agent
- 프로덕션 알람 오면 ateli가 1차 대응
- 로그 → 메트릭 → 트레이스 → 가설 → 임시 패치 → 사람 호출 (필요시)
- "DB 커넥션 풀 터짐. 임시로 풀 사이즈 2배로 올렸음. 근본 원인 분석은 아침에 시작함" 자동 보고

### 2.15. 🧙 Meta-Agent (에이전트 만드는 에이전트)
- 반복 작업 발견하면 그 작업 전용 서브에이전트 자동 생성
- "매주 금요일 보안 리포트 만드는 거 보니 이거 전용 에이전트 만들까?" 제안
- 사용자별 에이전트 라이브러리가 시간 지날수록 풍부해짐 = 락인

## 3. RAG를 변태같이 만드는 법

RAG가 평범하면 망함. ateli는 RAG로 승부봐야 함.

### 3.1. Multi-Layer RAG
- **레이어 1 (Lexical)**: BM25 + 키워드. 빠르고 정확한 식별자 검색.
- **레이어 2 (Semantic)**: 임베딩. 의미 기반 검색.
- **레이어 3 (AST-aware)**: Tree-sitter로 파싱해서 함수/클래스 단위 청킹. "이 함수 호출하는 모든 곳" 정확히.
- **레이어 4 (Graph)**: Import 그래프, 콜 그래프, 데이터 흐름 그래프.
- **레이어 5 (Temporal)**: Git 히스토리. "최근 3개월 안에 자주 바뀐 파일" 가중치.
- **레이어 6 (Social)**: 누가 어떤 코드 짰고, 누가 어떤 코드 자주 리뷰함.
- **레이어 7 (Behavioral)**: 사용자가 자주 여는 파일/검색하는 패턴.

이 7개 레이어 점수를 학습된 reranker로 합산.

### 3.2. Code-Aware Chunking
- 일반 RAG: 문자 단위 청킹 → 함수 중간 잘림 → 망함
- ateli: AST 노드 단위 청킹 + 함수 시그니처는 항상 포함 + 호출하는 함수 정의 같이 첨부
- "맥락 손실 0" 보장

### 3.3. Hierarchical Summarization (계층적 요약)
- 파일 → 요약, 디렉토리 → 요약, 모듈 → 요약, 시스템 → 요약
- 큰 코드베이스 들어와도 "전체 아키텍처" 한 줄 답변 가능
- 요약은 코드 변경 시 자동 무효화 → 재생성

### 3.4. Just-in-Time Indexing
- 코드 한 줄 바뀌면 영향받는 인덱스만 재계산 (전체 재인덱싱 안 함)
- 큰 monorepo도 실시간 반영

### 3.5. Personal Context Layer
- 사용자별 컨텍스트: 어떤 파일에 자주 작업하는지, 어떤 용어 쓰는지, 어떤 컨벤션 선호하는지
- "민수가 짜는 코드 스타일"과 "지수가 짜는 코드 스타일" 자동 구분 → 각자한테 맞춰 PR 생성

### 3.6. External Knowledge Federation
- 회사 외부 지식도 RAG에: Linear, Notion, Confluence, Google Drive, Slack, Discord, GitHub Issues, Sentry, Datadog
- 단, 권한 관리 빡세게: 사용자 권한 그대로 ateli도 따라감 (못 보는 거 못 가져옴)

### 3.7. Anti-Hallucination Guard
- RAG 결과로 답변 만들 때 모든 클레임에 citation 강제
- citation 없는 문장 자동 삭제
- "이거 어디서 봤어?" 질문에 항상 정확한 라인 번호 답변

## 4. 프롬프트 엔지니어링을 미친 수준으로

### 4.1. Persona Stacking
- 작업 종류별로 다른 페르소나 활성화
- 보안 작업 → "5년차 OWASP 트레이너" 페르소나
- 성능 작업 → "Brendan Gregg 제자" 페르소나
- UX 작업 → "Steve Krug 사도" 페르소나
- 각 페르소나마다 시스템 프롬프트 다름

### 4.2. Constitutional AI Layer
- 회사별 "헌법" 작성: "절대 PII 로그 안 찍음", "외부 API 호출은 항상 타임아웃 설정", "PR은 항상 테스트 포함"
- 모든 출력 이 헌법 위반 여부 자동 체크
- 위반 시 자동 수정 후 재출력

### 4.3. Few-Shot from Real History
- 프롬프트에 예시 박을 때 가짜 예시 X
- 그 회사의 실제 과거 PR/코드 리뷰에서 좋은 예시 자동 발췌
- "너희 회사 스타일" 그대로 출력

### 4.4. Meta-Prompting (프롬프트가 프롬프트를 만듦)
- 새 작업 들어오면 "이 작업에 최적화된 프롬프트" 자체 생성
- 작업 완료 후 결과 평가 → 프롬프트 개선 → 다음 비슷한 작업에 적용
- 시간 지날수록 회사별로 프롬프트가 진화함

### 4.5. Chain-of-Verification
- 답변 만든 후 자체 검증 질문 3개 생성 → 답변 → 일치 안 하면 다시 시작
- 환각 거의 박멸

### 4.6. Negative Prompting (안티패턴)
- "이런 식으로는 절대 짜지 마라" 명시
- 회사별 안티패턴 (지난 장애 원인이었던 코드 패턴 등) 자동 학습

## 5. 고객 맞춤 클라우드 (B2B 락인 전략)

### 5.1. 배포 모드 3종
1. **Multi-tenant SaaS**: 스타트업용. 빠르게 시작. 우리 클라우드.
2. **Single-tenant VPC**: 중견기업용. 고객 AWS/GCP 계정에 우리가 배포.
3. **Air-gapped On-prem**: 금융/정부용. 인터넷 없는 환경. 모델은 Bedrock/Vertex 프라이빗 엔드포인트.

### 5.2. Bring Your Own Cloud (BYOC)
- 고객이 자기 AWS 계정 연결 → 우리는 컨트롤 플레인만 관리
- 데이터는 절대 우리 인프라 안 거침
- 컴퓨트 비용은 고객이 직접 결제 → 우리는 SaaS 마진만

### 5.3. Bring Your Own Model (BYOM)
- 기본은 Anthropic API
- 고객이 원하면 Bedrock의 Claude, Vertex의 Claude, 자체 호스팅 Llama 등 라우팅 가능
- 모델 추상화 레이어로 어떤 모델이든 꽂힘

### 5.4. Per-Tenant Knowledge Isolation
- RAG 인덱스, 임베딩, 학습된 reranker 모두 테넌트별 격리
- 한 고객 데이터로 학습한 게 다른 고객한테 절대 안 새어나감
- 이거 계약서에 박아넣기

### 5.5. 데이터 주권 옵션
- 데이터 위치: 한국/일본/미국/EU/싱가폴 중 선택
- 모든 LLM 호출 로그 고객 S3에 직접 저장
- GDPR/HIPAA/SOC2/ISO27001 인증 받기 (필수)

### 5.6. Cost Transparency
- 작업당 토큰 사용량 + 인프라 비용 실시간 대시보드
- "이번 달 ateli가 짠 PR 47개, 토큰 $312, 컴퓨트 $89, 합계 $401" 명세서
- 절약된 엔지니어 시간 추정도 같이 보여줌 (ROI 어필)

## 6. 멀티 서피스 (모든 곳에서 접근)

같은 에이전트, 다른 입구. 컨텍스트는 항상 동기화.

### 6.1. 채팅 플랫폼
- Slack (1순위)
- Discord (스타트업 많음)
- Microsoft Teams (엔터프라이즈 필수)
- 카카오톡 / 라인 (아시아 시장)
- Telegram

### 6.2. IDE

## 10. 기술 스택 (제안)

### 백엔드
- 언어: TypeScript (에이전트 오케스트레이션) + Python (ML/RAG) + Rust (성능 크리티컬)
- 오케스트레이션: 자체 빌드 (LangGraph 같은 거 안 씀, 너무 무거움)
- 큐: Temporal (장기 실행 워크플로우)
- DB: Postgres + pgvector + ClickHouse (분석)
- 벡터 DB: 자체 호스팅 Qdrant 또는 Turbopuffer

### 인프라
- K8s on AWS (멀티 리전)
- Firecracker VM (격리된 코드 실행)
- Tigris/R2 (객체 저장, 멀티 리전 자동)
- Cloudflare (엣지)

### 관측성
- OpenTelemetry 전체
- 자체 LLM 트레이싱 (LangSmith 안 씀, 데이터 우리가 갖고 있어야)

### 보안
- Vault (시크릿)
- 모든 코드 실행은 ephemeral container
- gVisor + Firecracker 이중 격리
